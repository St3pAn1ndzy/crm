# Django CRM
Высокотехнологичная **CRM-система**, разработанная для автоматизации бизнес-процессов: от привлечения лидов маркетинговыми кампаниями до долгосрочного закрытия контрактов. Построенная на базе **Django 6.1**, система переведена из локальной разработки в масштабируемую продакшн-экосистему с помощью кэширования в **Redis**, сквозного мониторинга **Prometheus & Grafana** и агрегации логов **Loki & Promtail**, полностью контейнеризированных через **Docker Compose**.

### 🏗️ Архитектура Системы и Возможности

Проект спроектирован по принципам чистой архитектуры с изоляцией бизнес-логики от инфраструктурного слоя, что гарантирует высокую скорость работы и отказоустойчивость.
```ini
🌐 Веб-сервер Nginx (Порт 80/8080)
├── 📂 /static/ & /media/ (Раздача статики напрямую с диска через Volumes)
└── 🔀 Proxy Pass ➡️ Gunicorn WSGI (Порт 8000)
└── 🐍 Ядро Django CRM Application
├── 🗄️ PostgreSQL 16 (Реляционная база данных)
├── ⚡ Redis (Низкоуровневый Cache API)
└── 📊 Prometheus Metrics Exporter ➡️ Мониторинг Grafana
```
#### 💎 Ключевые Технологические Особенности

* **Промышленный веб-сервер (Nginx + Gunicorn):** Веб-сервер **Gunicorn** запущен в многопоточном режиме обработки запросов, скрываясь за обратным прокси-сервером **Nginx**. Nginx выступает главным щитом системы, обрабатывая входящие соединения, пробрасывая заголовки оригинальных IP-адресов клиентов и полностью забирая на себя сверхбыструю раздачу тяжелых файлов статики и медиа с жесткого диска, разгружая процессы Python.
* **Целостность данных и Мягкое Удаление (Soft Deletes):** На уровне Django ORM написаны кастомные менеджеры запросов, реализующие безопасное архивное удаление (`is_active=False`) для услуг, рекламы и контрактов. Это исключает физическое стирание строк из PostgreSQL, сохраняя полную аудиторскую историю компании и защищая сквозную финансовую аналитику от искажения.
* **Транзакционная безопасность (`@transaction.atomic`):** Все сквозные операции над несколькими таблицами (например, перевод лида в статус клиента с одновременным расчетом и генерацией его первого контракта) строго обернуты в SQL-транзакции. При сбое на любом этапе (ошибка валидации, потеря связи с Redis) база данных полностью откатывается к исходному состоянию, исключая появление «битых» или дублирующих записей.
* **Автоматизированная ролевая модель доступа (RBAC):** Стандартные группы прав Django расширены кастомной моделью `User` с переопределенным методом `.save()`. При изменении роли сотрудника в административной панели («Оператор», «Маркетолог», «Менеджер»), система на уровне кода автоматически пересчитывает и синхронизирует его системные допуски к таблицам (`add_customer`, `view_contract` и т.д.).
* **Контроль качества кода CI/CD:** Настроен автоматический пайплайн GitHub Actions, запускающий современный линтер **Ruff** при каждом пуше в ветки `main` и `develop`, блокируя попадание синтаксических ошибок или неоптимальных импортов в общий репозиторий.

### 🚀 Оптимизация Производительности, SQL и Кэширования

Архитектура CRM спроектирована так, чтобы минимизировать нагрузку на базу данных и гарантировать мгновенный отклик страниц под высокой нагрузкой.

#### 🛑 Устранение проблемы N+1 запросов
Стандартные списки данных, выводящие связанные внешние ключи, способны намертво перегрузить базу данных из-за сотен микро-запросов к Postgres. За счет внедрения ORM-оптимизации **`select_related`**, тяжелые выборки (например, выгрузка списка Контрактов с одновременным выводом ФИО Клиента и его Лида) компилируются в один высокоэффективный SQL-запрос через оператор **`JOIN`**, снижая количество запросов к БД с `N+1` до строго **`1`**.

#### ⚡ Низкоуровневый быстрый кэш на Redis
Сбор сквозной аналитики успешности рекламы (подсчет уникальных лидов, конвертированных активных покупателей и суммирование чистой прибыли через агрегации `Count` и `Sum` по четырем таблицам) — это самая ресурсозатратная операция в CRM.
* **Стратегия кэширования:** Данные отчета рассчитываются один раз, преобразуются в чистый Python-список с помощью `list()` и записываются в оперативную память **Redis** на 24 часа. Все последующие открытия этой страницы менеджерами происходят за сотые доли секунды напрямую из ОЗУ.
* **Умная инвалидация (Сброс кэша):** Чтобы руководство всегда видело актуальные финансовые отчеты, в систему внедрена реактивная инвалидация кэша. В ту же секунду, когда в CRM создается, редактируется или уходит в архив лид или контракт, система выполняет команду `cache.delete()`, принудительно обновляя дашборд только при реальном изменении данных.

### 👁️ Мониторинг и Логирование (Full-Stack Observability)

Инфраструктура включает в себя полноценный комплекс телеметрии, позволяющий в реальном времени отслеживать здоровье сервера, ошибки и действия пользователей.

* **Сбор системных метрик (Prometheus):** Middleware-модуль `django-prometheus` непрерывно собирает данные о времени ответа вьюх, объеме сетевого трафика, количестве HTTP-запросов, состоянии пула подключений PostgreSQL и эффективности кэша Redis.
* **Агрегация логов (Grafana Loki & Promtail):** Настроен системный логгер Django, пишущий все важные действия сотрудников (вход, создание документов, ошибки транзакций) в изолированный файл `crm.log`. Легковесный агент **Promtail** непрерывно сканирует этот файл и пересылает строки логов в базу данных **Loki**.
* **Автоматические дашборды (Grafana Provisioning):** Реализован принцип «Мониторинг как код». Все настройки баз метрик и конфигурация панелей вынесены в файлы настроек `/provisioning/`. При первом же старте проекта в Grafana автоматически разворачивается дашборд, выводящий интерактивные графики и живой терминал логов на одном экране.

## 🛠️ Конфигурация Переменных Окружения (`.env`)

Создайте файл `.env` в корневом подкаталоге приложения `crm/`. Шаблон для безопасной настройки системы:

```ini
# Секретные настройки Django
SECRET_KEY=django-insecure-your-actual-secret-key-here
DEBUG=False
ALLOWED_HOSTS=

# Доверенные адреса для защиты CSRF (без пробелов, через запятую)
CSRF_TRUSTED_ORIGINS=

# Настройки PostgreSQL для контейнера 'db'
POSTGRES_DB=crm_db
POSTGRES_USER=crm_user
POSTGRES_PASSWORD=crm_password

# Сквозные URL-строки подключения для Django (смотрим на имена сервисов db и redis!)
DATABASE_URL=postgres://crm_user:crm_password@db:5432/crm_db
REDIS_URL=redis://redis:6379/1

# Настройки Grafana
GF_SECURITY_ADMIN_PASSWORD=password

```

## 📦 Руководство по Быстрому Запуску (Quick Start)

Инфраструктура спроектирована для автоматического развертывания всего стека одной командой.

### Предварительные требования
* Установленный Docker и Docker Compose.
* Свободные порты `8080` (или `80`) и `3000` на вашем локальном компьютере.

### Шаг 1: Запуск контейнеров в фоновом режиме
Из папки проекта, где находится файл `docker-compose.yml`, запустите сборку:
```bash
docker compose up --build -d
```
*Docker автоматически прочитает файл `.dockerignore`, оставив тяжелые локальные папки `.venv` и кэш IDE за бортом контейнера, гарантируя чистоту и высокую скорость сборки образа.*

### Шаг 2: Создание учетной записи Администратора
Сгенерируйте профиль главного администратора для управления персоналом:
```bash
docker exec -it crm-web python manage.py createsuperuser
```
